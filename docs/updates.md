# Обновления DROP

[← Инструкция](usage.md) · [Все релизы](https://github.com/cveloy102/hl100-drop/releases)

## Проверка из самих приложений

На устройствах оставьте **1.1.0**, затем:

1. Откройте настройки DROP и нажмите **«Проверить обновления»**.
2. Должна появиться **1.1.1** и предложение обновиться. В основном окне доступна плашка нового релиза.
3. Нажмите **«Обновиться»**. Дождитесь окончания загрузки и проверки контрольной суммы.
4. Завершите установку по правилам своей платформы ниже.
5. Откройте настройки и убедитесь, что отображается **1.1.1**, имя и папка сохранились. Проверьте небольшую передачу в обе стороны.
6. Повторная проверка не должна предлагать ту же версию снова.

Не устанавливайте 1.1.1 вручную заранее, если хотите проверить весь сценарий обновления. Если версия уже новая, для проверки доступна предыдущая 1.1.0 из [истории релизов](https://github.com/cveloy102/hl100-drop/releases/tag/v1.1.0); на Android откат с большим versionCode может быть запрещён системой, поэтому не удаляйте приложение ради теста.

## Windows

DROP загружает `.exe`, проверяет SHA-256 и запускает установщик. Завершите установку и откройте приложение из меню «Пуск». Настройки хранятся отдельно от программы и сохраняются при замене версии. Обновление лучше запускать после завершения передач.

## Android

Загружается релизный `.apk`, проверяется SHA-256 и открывается системная установка. Подтвердите обновление; Android может запросить разрешение установки из DROP. APK подписан постоянным ключом, versionCode растёт между выпусками. Debug APK из CI не предназначен для обновления релизной версии.

## macOS

Загружается универсальный `.dmg`, проверяется SHA-256 и открывается образ. Закройте DROP через меню приложения и замените **HL100 Drop.app** в **«Программах»**. Затем запустите его снова. Исходники и Xcode для этого не нужны. Сборка ad hoc, без нотариализации Apple; системное разрешение запуска может потребоваться снова.

## Канал обновлений

Источник — `https://api.github.com/repos/cveloy102/hl100-drop/releases/latest`.
Все три клиента читают последний стабильный GitHub Release. Предварительные релизы не показываются как обновления. Файлы именуются по версии:

| Платформа | Файл |
| --- | --- |
| Windows | `HL100DropSetup-<версия>.exe` |
| Android | `HL100Drop-<версия>.apk` |
| Mac | `HL100Drop-<версия>-universal.dmg` |
| Контрольные суммы | `checksums.txt` |

Обмен внутри LAN работает без интернета. Интернет нужен только для обращения к GitHub и загрузки обновления. Автоматическая установка без действия пользователя не выполняется.
