# Протокол HL100 Drop v1

IPv4 TCP напрямую между устройствами в одной подсети; loopback разрешён для тестов. Нет аккаунтов, сопряжения, TLS, сжатия, relay, облачного обмена и переключения на публичный адрес. IPv6 и маршрутизация между подсетями вне v1.

## Обнаружение

UDP 41001, multicast `239.255.100.100`, TTL=1 и broadcast интерфейса. Объявления каждые 2 секунды; устройство истекает через 7 секунд.

```json
{"app":"hl100-drop","protocol":1,"id":"persistent-device-id","name":"Мой ПК","port":41000,"platform":"windows","resume":true}
```

## Передача

TCP по умолчанию 41000. Управляющий кадр: длина UTF-8 JSON как 4-байтовое unsigned big-endian число, затем JSON, максимум 4 МиБ.

1. Предложение: `{protocol:1,id,name,transfer,entries:[{path,size,directory}]}`. Разделитель пути `/`, каталог в сетевом манифесте имеет размер 0.
2. Ответ: `{ok:true}` либо `{ok:false,error}`.
3. Каждый файл передаёт ровно `size` сырых байтов, получатель завершает запись и отвечает ACK. Каталоги не передают байты и не получают отдельный ACK.
4. После всего манифеста — итоговый ACK; только после него отправитель сообщает завершение.

Получатель резервирует свободное корневое имя, сохраняет существующие файлы, пишет части и переименовывает готовые файлы. В старом режиме при сбое части удаляются; готовые файлы остаются. Пустые папки сохраняются. Небезопасные относительные пути отклоняются; symlink не отправляются.

Буфер 1 МиБ, прогресс не чаще 150 мс, тайм-аут сетевой операции 15 секунд. Старый режим повторяет новую передачу; 1.1 согласует докачку.

## C ABI / JNI

`hl100_command` возвращает строку UTF-8 JSON во владение клиента; освободить через `hl100_free`.

```json
{"op":"start","config":{"id":"persistent-id","name":"ПК","folder":"receive-path","port":41000}}
{"op":"poll"}
{"op":"send","address":"192.168.1.2","port":41000,"name":"Телефон","paths":["C:/files/report.pdf"]}
{"op":"pause","transfer":"local-transfer-id"}
{"op":"resume","transfer":"local-transfer-id"}
{"op":"cancel","transfer":"local-transfer-id"}
{"op":"stop"}
```

`poll`: `peers`, `events`, `busy`. События: `started`, `transfer`, `file`, `state`, `progress`, `complete`, `error`. `complete.status`: `done`, `cancelled`, `error`. Ошибка команды: `{ok:false,error}`. `busy` — активный ввод-вывод; ручная пауза не блокирует выход / обновление.

Android использует JNI и content URI. Источник открывается лениво; запись идёт прямо в SAF-дескриптор, завершение переименовывает документ, промежуточная копия не требуется.

## Метаданные интерфейса

`transfer.entries` — первые 200 элементов манифеста; `files` — полный счётчик, `total` — все байты. `display_entries` / `display_count` описывают верхний уровень для UI: папка — один объект с суммарным размером.

В режиме докачки `file` публикуется для видимого готового файла или корневой папки после завершения всей группы. Поля: `transfer`, `path`, `size`, `directory`, `local_path`. Дисковое хранилище возвращает фактический путь с коллизией; SAF без файлового пути возвращает null. Незавершённый объект не открывается. Это локальные поля C ABI / JNI, не новая версия сетевого протокола.

## Докачка · DROP 1.1

Отправитель дополняет предложение `resume:true`, стабильным безопасным ASCII-ID и необязательным `action:"cancel"`. Старый получатель игнорирует поля и отвечает `{ok:true}`; отправитель работает без паузы.

Новый ответ: `{ok:true,resume:true,id,offsets:[[writtenBytes,finished],...]}` по манифесту. Смещения — фактические длины частей / готовых файлов получателя, не прогресс отправителя.

Незавершённый файл передаёт `size-writtenBytes` байтов с обычным ACK. Готовый — без байтов и отдельного ACK. Итоговый ACK тот же; управляющие кадры не вставляются в поток. Пауза закрывает сокет, новое предложение согласует смещения. `paused` / `busy` откладывают повтор, `cancelled` прекращает его. Стабильный ID защищает от докачки другому устройству после смены IP.

Получатель сверяет ID отправителя и манифест с журналом. Сохраняются части, пауза и корневые имена; готовое пропускается. Перед открытием оригинала проверяются размер и время изменения. Отмена удаляет части и оставляет готовое; выключенному получателю она доставляется после возвращения.

`state`: `status` (`active`, `waiting`, `paused`) и `resumable`. Журналы: `.drop-state` в папке приёма, Android private storage и SAF URI. Сброс на границах файлов / переходах состояния, без fsync / ACK на каждый блок, сжатия или prehash. Обычный перезапуск поддерживается; внезапное отключение питания или внешняя правка частей не имеют транзакционной гарантии.
